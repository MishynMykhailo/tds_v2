# Раунд 3 — Fork A: Campaigns, Streams, Offers, Landings

Тестирование через Playwright (тот же контейнер `tds-playwright`, рабочая директория `/work/forkA/`,
логин `admin`/`TdsAdmin2026!`). Использовался campaign id=5 ("PW Full Test Campaign 2", создан в
рамках теста), а также существующие сущности из предыдущих раундов (campaign id=4 "test").

**Важное замечание по методологии**: real-click-эмуляция через `page.locator(...).click()` часто
не срабатывала на вкладках `uib-tabset` и на react-select дропдаунах внутри модалок этого
приложения (Playwright ругался "element is not visible"/"outside of the viewport", хотя элемент
визуально присутствовал и был кликабелен человеком). Рабочий обход: считать
`getBoundingClientRect()` через `page.evaluate()` и кликать по реальным координатам через
`page.mouse.click(x, y)` — сработало во всех случаях. Стоит учитывать этот нюанс при
автоматизации UI-тестов этого проекта в будущем (похоже на CSS/трансформ-эффект модалок, из-за
которого Playwright's actionability-эвристика ошибается, хотя реальный рендеринг в порядке).

## Campaigns

### ✅ Подтверждено работающим
- Создание кампании с полным набором данных: имя, alias, traffic loss, алиасы параметров
  (`keyword`, `sub_id_1`) на вкладке Parameters, заметка на вкладке Notes — всё сохраняется
  корректно в БД (`?object=campaigns.create` → 200, проверено прямым GET `campaigns.index`
  после создания — все поля на месте).
- Формли-вкладки Settings/Integration/Parameters/S2S Postbacks/Notes — все поля из этих вкладок
  РЕАЛЬНО присутствуют в DOM одновременно (Angular не размонтирует неактивные табы), это упростило
  тестирование, но также означает, что фронтенд держит довольно тяжёлое DOM-дерево формы кампании
  постоянно в памяти.
- Кнопка "Save" кампании (`?object=campaigns.update`) сохраняет и саму кампанию, и ВСЕ staged-
  изменения по стримам (создание/редактирование стрима внутри React-виджета) одним запросом —
  подтверждено: стрим, добавленный через "Create Stream" → "Apply", исчезает после релоада
  страницы, ЕСЛИ не нажать после этого кампанийный "Save"; если нажать "Save" — переживает релоад.
  **Это ожидаемое поведение (двухступенчатое сохранение), не баг**, но обязательно задокументировать
  для пересборки фронтенда: "Apply" в модалке стрима = staging в памяти клиента, реальная запись в
  БД происходит только через `campaigns.update` с вложенным массивом `streams`.

### 🐛 НАЙДЕН РЕАЛЬНЫЙ БАГ (фронтенд): нет обратной связи после создания кампании

После успешного `?object=campaigns.create` (HTTP 200, кампания реально появляется в БД с новым
id) UI **не переходит** на страницу созданной кампании (`#!/campaigns/<id>`) и **не показывает
подтверждения** — вместо этого форма "Create" визуально сбрасывается в состояние "нового пустого
создания" (поле имени снова показывает placeholder "Campaign name", список стримов справа
показывает "There is no streams yet.", хотя реальный URL всё ещё `#!/campaigns/create`).

Воспроизведено дважды: и через синтетический JS-клик (`element.click()` из `page.evaluate`), и
через настоящий Playwright-клик мышью по кнопке "Create" — результат идентичный в обоих случаях,
значит это не артефакт автоматизации, а реальное поведение бандла.

**Риск для реального пользователя**: создав кампанию, пользователь не видит подтверждения успеха и
может решить, что клик не сработал, и нажать "Create" ЕЩЁ РАЗ. В моих тестах повторный клик не
создавал дубликат (проверено — после первого успешного создания id=5, второй тестовый клик на
свежей `#!/campaigns/create` странице создал ожидаемый следующий id=6 с ДРУГИМ именем, т.к. я
явно менял имя каждый раз) — но если пользователь введёт то же имя и нажмёт Create второй раз
не заметив, что первая кампания уже создана, это создаст дубликат кампании с одинаковым именем
(бэкенд не проверяет уникальность имени кампании).

**Тип бага**: чисто фронтенд (в `admin/assets/app.js`, минифицированный бандл, нет доступа к
исходнику для точечного фикса в рамках этой сессии). Логика создания, судя по всему, не делает
`$state.go('campaigns.edit', {id: response.id})` (или аналог) после успешного `create()`-промиса,
как это сделано для многих других сущностей. **Стоит исправить при пересборке фронтенда** —
занести в `docs/frontend/questions_for_new_proj.md`/`architecture_plan.md`.

### ⚠️ Минорное: JS console error при открытии формы создания кампании

`TypeError: Cannot read properties of undefined (reading 'setColumns')` at `app.js:107137` —
происходит сразу при открытии модалки "Create" (до заполнения полей). Судя по контексту (это
код `gridReact`/react2angular моста, см. `docs/frontend/frontend_analysis.md` §1), похоже на
попытку обновить колонки грида кампаний в фоне, пока открыта модалка создания — не мешает
дальнейшей работе формы (создание всё равно проходит успешно), но грязный console.error,
достойный внимания при пересборке.

## Streams

1. **`action`** — создан стрим со схемой Action, действие "404 NotFound" — сохранился, пережил

2. **`redirect`** ("Direct URL") — создан стрим с `action_payload = https://example.com/redirect-test`
   — сохранился и пережил релоад.
3. **`landings`** ("Landing pages & offers") — не создавал заново (уже подтверждено в раунде 1 на
   campaign id=4), в этом раунде переиспользовал существующий пример для проверки UI (оба пикера,
   Landing Pages и Offers, действительно показываются одновременно под одним радио — см. предыдущий
   раунд, скриншот `stream_schema_landings.png`).

### ⚠️ Наблюдение: в дропдауне "Action" при schema=action всего 5 вариантов, не ~9-10

Ожидалось (по документации `backend_api_reference.md`/`streamActions.index`): `curl, show_text,
show_html, local_file, 404, to_campaign, frame, iframe, sub_id, do_nothing` (~10 типов). Реально
в открывшемся react-select дропдауне для СТРИМА со схемой `action` видно только 5: **"Send to
campaign", "404 NotFound", "Show as text", "Show as HTML", "Do nothing"**. Отсутствуют: Curl,
Frame, Iframe, Sub id, Local file.

Не выяснено окончательно, баг ли это (например, фронтенд передаёт `exclude-actions` проп на
компонент `<stream-actions>`, аналогично уже известному пофикшенному случаю с Offer/Landing форм,
см. `docs/FIXES_LOG.md` "Фронтенд" раздел — `exclude-actions="['curl', 'local_file']"`) или
осознанное ограничение (возможно, Curl/Frame/Iframe/Sub id/Local file не имеют смысла на уровне
СТРИМА и доступны только на уровне Offer/Landing). **Стоит перепроверить руками** — открыть форму
стрима в реальном (не тестовом) окружении и явно посчитать варианты, либо погрепать в `app.js`
конкретный `exclude-actions` проп у компонента `<stream-actions>` внутри `streamForm`.

### ⚠️ Минорное: фильтр можно сохранить без выбранного значения

Добавил фильтр "Country" в Filters, НЕ выбрав конкретную страну (react-select для стран не
показал опций на "United" — возможно, проблема теста, а не бага, но не успел перепроверить), и
всё равно смог нажать Apply → Save — фильтр сохранился как **"Country is ''"** (пустая строка).
Нет клиентской валидации "выберите хотя бы одно значение фильтра" перед сохранением. Не
критично, но при пересборке стоит добавить валидацию — пустой фильтр не имеет смысла и может
привести к неожиданному поведению в клик-пайплайне (нужно проверить, как `StreamFilter` с
пустым `payload.values` ведёт себя в `Traffic\Model\StreamFilter`/фильтрах трафика — не
проверялось в рамках этого раунда, чисто фронтенд-наблюдение).
